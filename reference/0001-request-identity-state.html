Keep these terms distinct

HTTP request / response
A client sends a method, target, headers, and sometimes a body. A server returns a status, headers, and sometimes a body.
DOM
The browser's document representation. JavaScript can update what appears on the page after a response arrives.
Password hash
A verifier produced by a dedicated password hashing scheme. Use established verification libraries; hashing is different from reversible encryption.
Cookie
A browser-held value sent with requests matching its scope and browser rules. A cookie can carry a session identifier; the cookie itself is not proof of permission.
Server-backed session
In the illustrated design, an unpredictable identifier refers to server-held identity and validity state. The server checks that state on later requests.
sessionStorage
A browser storage API. Its name does not make its contents an authenticated server session.
Cache key
The identity of a cached result. Include the context that changes the result and respect current permissions.
Hit / miss
A hit reuses an eligible cached result. A miss computes or fetches the result and may cache it.
TTL
Time to live: an expiry duration. It bounds reuse in a particular cache; it does not guarantee immediate freshness or user isolation.
Invalidation
Making an existing cached result unavailable or unusable, for example after a relevant change.

When an observation looks wrong

  1. Separate response from display. Inspect the actual request and body in Network. HTTP 200 alone does not establish product correctness.
  2. Trace trusted identity. Find how the server validates it. Editing a browser user ID must not switch the authenticated identity.
  3. Trace every return path. A database ownership filter cannot protect a cache hit that bypasses it.
  4. Test the failure mode. Use distinct identities, an empty then warm cache, and both request orders where relevant. Two tabs may share one login.
  5. State the evidence and its limits. A passing example supports that behaviour; it is not proof of every possible case.

For a server-backed session, expiry and logout must be enforced by the server. Removing only a browser value does not necessarily invalidate a captured session identifier.
