Boundaries, failures, and effects

Recall first, then use this compact guide. Detailed primary references live in each lesson.

← Learning workspace

Origin and CORS

Origin is scheme, host and effective port. A simple cross-origin request can arrive while its response remains unreadable to page JavaScript. A failed preflight can prevent the actual request. CORS does not establish identity, permission or complete CSRF protection.

Test boundaries

A pure-rule check does not exercise storage schema, HTTP or deployment. Include the relevant result and side effect, especially no write on invalid input. A mock cannot prove the real SQL works.

Transactions and replay

Stale reads outside a protecting transaction can support wrong decisions. For a bounded stock rule, conditional decrement plus an affected-row check protects the sale. Keep its database effects together. Stable external IDs and an explicit update/reject contract support replay; database idempotency does not automatically cover external writes.

DNS, TLS and upstreams

DNS locates an address; TLS validates a peer connection; Nginx may then open a separate upstream connection. Inspect the first failing boundary. A 502 has multiple possible causes. HTTP proxying and PHP-FPM FastCGI configuration use different protocols.

Acceptance evidence

State actor, initial state, trigger, observation and conditions. Tool installation is not a user outcome. Freshness, response cost and isolation are separate requirements. A single sample does not establish a percentile or future service guarantee.

Logs and error events

Correlate operation identity, release, stage and outcome. A Sentry event reports an occurrence; an issue groups related events. Capturing evidence does not repair the failure. Use a narrow context schema and review actual values; never assume default scrubbing proves arbitrary data safe.

Input trust

Bind SQL values, including the authenticated ownership scope. Use fixed mappings for identifiers. Distinguish SQL injection, XSS browser-code execution and CSRF induced authenticated actions. HTTPS alone does not prevent them.
