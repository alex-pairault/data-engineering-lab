Interface contracts

Check method, path, input constraints, response types, status/error meaning, and pagination. A specification describes the promise; implementation and tests enforce it. HTTP 200 does not establish shape compatibility. 

Request valid? → Documented status + body → Existing client still accepts it?

Adding an optional field may be compatible when consumers tolerate it. Removing a field, changing its type, or adding a required request field can break consumers. Verify them.

Elapsed time
Duration between perf_counter calls, including waits.
Process CPU time
Current-process user/system CPU time between process_time calls; excludes sleep. Elapsed minus CPU is not an exact disk-I/O measurement.
Traced peak allocations
The peak of the Python allocations tracemalloc tracks. It is not total process or system memory.
Peak RSS
A process memory high-water mark. It includes baseline memory, and platform reporting differs. Use a fresh process per case when comparing peaks.
Streaming / batching
Bound how many records remain live, provided input records and retained results are also bounded. This can reduce memory without guaranteeing faster execution.

Verify equal output, compare two input sizes, and describe measurement limits. Separate allocation tracing from timing runs; account for warm file caches. More cores or workers do not automatically accelerate a serial workload.

Preserve SQL groups before filling values

LEFT JOIN → WHERE → GROUP BY / SUM

-- Preserve each customer; match only qualifying orders.
LEFT JOIN orders o
  ON o.customer_id = c.id AND o.status = 'paid'

-- Zero for a retained group with no qualifying amount.
COALESCE(SUM(o.amount), 0)

A right-side WHERE filter can remove the null-extended rows and customers with only excluded orders. COALESCE cannot restore a missing group. CASE with an explicit ELSE 0 is another solution for this fixture. Test no orders, excluded-only orders, multiple paid orders, and a paid zero.

Lifetime, freshness, and invalidation

Fixed TTL
The entry's reuse lifetime in this model. A source change can make a live entry stale; expiry itself does not load a replacement.
Cache-aside miss
The application loads from the source on a miss, then stores the result. Source freshness and failure/race behaviour affect what gets cached.
Early-deletion race
Delete → reader refills old source → writer commits → stale cache survives.
After-commit deletion
Invalidate after a successful commit for this ordering problem. Rollback should not run the callback. Failures or late in-flight refills need additional handling.

One useful verification habit

Predict a result, run the changed example, inspect the returned values, and state what the evidence supports. Include a negative or edge case relevant to the mechanism. Bring your own explanation and follow-up questions to your teaching agent.
