Data, delivery, and evidence

Recall first, then use this compact guide. Detailed primary references live in each lesson.

← Learning workspace

dbt and data assertions

Document one-row meaning before trusting a model. Data tests query current violations; they are not future-write constraints. Default zero-failure success can be changed by configuration. Relationships and accepted_values need separate not_null checks when missingness is invalid. Test input assumptions before filters or aggregation hide them.

Python and network boundaries

Distinguish transport, HTTP, parse and schema failures. Keep failure explicit. Use per-attempt timeouts and bounded retry policy. A POST timeout can leave a committed effect uncertain; retry only according to its business contract.

Containers and replicas

Inside an ordinary bridge container, localhost is that container. Peers use service names and internal ports; hosts use published ports. Healthchecks gate initial readiness only. Named volumes survive ordinary replacement. Affinity does not replicate sessions; shared state needs design, including when Kubernetes manages routing.

Context and CI

Bound a task with user need, relevant sources, invariants, acceptance cases, verification and a stop condition. Review the final diff independently. Tie check results, build artifact and deployment to the intended source identity. Green CI establishes its assertions, not every production behaviour.

Workflow, queue and Airflow

A schedule creates runs; dependencies order work; queues distribute jobs; webhooks deliver HTTP events. Acknowledgement failure can cause redelivery. Airflow retries=1 permits two attempts. Local dag.test() is not a production distributed-executor check. Clearing or retrying tasks does not undo external effects.

Plans and resource evidence

Count N+1 accesses and verify equal results after batching. Bound batches and memory. A plan is not a timing guarantee; PostgreSQL EXPLAIN ANALYZE executes the statement. Indexes add storage/write costs and do not improve every query.

Recovery and compatibility

Code rollback is not deleted-data recovery. Restore into a separate disposable target and verify rows, schema and a business assertion. An older snapshot can omit later writes. Plan compatible schema evolution, acceptable recovery point and reconciliation.

Interview and capstone

State assumptions, trace a mechanism, test a changed case and name limits. Reuse one existing slice for the capstone. Record your actual commands/results, changed case, reasoning and assistance using the exercise template. Generated scaffolding, guided practice, independent demonstration and later retention are distinct.
