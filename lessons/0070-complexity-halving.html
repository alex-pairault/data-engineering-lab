log₂ n answers “how many doublings reach n?” Equivalently, it counts repeated halvings toward one. log₂ 8 = 3 because 2 × 2 × 2 = 8. If the input doubles, this logarithm increases by one; it does not double.

Binary search uses sorted random-access data. Probe the midpoint, then keep the only half that can contain the target. For a nonempty length n, the implementation needs at most floor(log₂ n)+1 midpoint probes. A probe may execute two value comparisons; probes are the unit counted here.

Keep low and high indices, not sliced sublists. Copying slices adds work and memory. Sorting unsorted input first has its own cost, so a one-off sort-plus-search is not just O(log n). The exact early-exit path can be cheaper than the worst case.
