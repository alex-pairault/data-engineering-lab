02 / EXPLORE

Follow the mechanism.

→

→
Review evidencetwo users; both orders

Review the actual final diff and its behaviour, not the agent’s completion summary. A claim such as “query is now user-scoped” can be true while another return path remains unsafe.

The candidate patch leaves the warm cache path under a shared key. A single-user happy-path test passes. A second user can then receive the first user’s cached records without the scoped query running. Check both user orders, warm hits, and required data presence; an empty success response is not a valid isolation repair.

A useful review finding states the trigger, consequence, evidence and required boundary. For example: after A warms the cache, B receives A’s records because the hit path does not use B’s identity. Link the behaviour to a failing regression case, then check the repaired implementation against the same cases.

Review correctness, readability, architecture, security and resource behaviour at a scale appropriate to the change. Tests themselves need review: would the broken code fail them, and do assertions verify the business outcome? Record limitations such as revocation, tenant scope or error paths left outside the tested slice.
