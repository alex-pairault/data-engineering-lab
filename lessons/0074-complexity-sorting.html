02 / EXPLORE

One mechanism to use today.

Split levelsroughly log₂ n
→
Merge each levellinear work across n values
→
Combined growthO(n log n) worst-case sorting

A merge combines two already sorted inputs by repeatedly taking the smaller next item. With lengths a and b, every item is emitted once: O(a+b) time and O(a+b) result storage. The comparisons are bounded by a+b−1 when both inputs are nonempty.

Merge sort repeatedly halves the input, then merges the pieces. It has roughly log₂ n levels and O(n) merge work per level, producing O(n log n) worst-case growth. Our browser n×log₂ n curve illustrates the family; it is not an exact Python sort operation count. Python uses an adaptive merge-based algorithm and can exploit existing order.

As an optional recognition step, 2ⁿ means multiplying 2 by itself n times, and n! (factorial) means n × (n−1) × … × 1; for example, 4! = 4 × 3 × 2 × 1 = 24. Also recognize explosive candidate counts: n distinct yes/no choices have 2ⁿ subsets; arranging n distinct items has n! possible orders. Producing copies of all candidates adds per-output work and storage, so these counts alone are not complete materialization runtimes. We calculate counts only, with a tiny bounded n. 

# Two sorted heads; emit only one per iteration.
while i < len(left) and j < len(right):
    if left[i] <= right[j]:
        ... # emit left[i], advance i
    else:
        ... # emit right[j], advance j
# Then emit each remaining item once.
