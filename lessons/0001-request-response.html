Trace a browser request and separate the received response from what the page displays.

02 / EXPLORE

Follow the mechanism.

A displayed value has travelled through several decisions. Start by finding where the observation changes.

A response is evidence

The server returns a status, headers, and a body. Inspect the body that actually arrived, rather than assuming the database value reached the page.

A page is another observation

JavaScript and browser state may decide how that response is displayed. A correct response does not automatically update an old value already on screen.

In a typical web system, the browser sends a request to a web server, which may forward it to an application. The application may query a database. The result travels back as a response. Some requests are served without all those steps, for example from a cache.

HTTP 200 is a narrow signal: the HTTP operation succeeded. It does not prove that the returned data, later requests, or rendered interface satisfy the product requirement.

Investigate before changing

  1. Find the request supplying the value in the browser’s Network panel.
  2. Inspect its status and response body.
  3. Compare that evidence with the displayed value.
  4. State a hypothesis, then choose a check that could disprove it.
