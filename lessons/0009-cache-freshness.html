How old may this value be?

Distinguish cache lifetime from source freshness and verify reload after expiry.

02 / EXPLORE

Follow the mechanism.

A cache hit reuses an eligible entry. A miss loads a value from its source. In this cache-aside model, the application fills the cache after a miss.

Lifetime

A fixed TTL, or time to live, controls how long this entry remains eligible for reuse after loading. Reading it does not extend that lifetime in this model.

Freshness

A value is stale when it no longer represents the relevant source state. A source update can make an unexpired entry stale immediately.

At t=0 the cache loads 100. The source becomes 120 while that entry is live. A hit can still return 100. After expiry, the next read misses and loads 120. Expiry itself does not fetch a replacement.

Ask a product question before choosing a number: “How long may a user see an old value after a change?” A public report and a permission decision can have different requirements. Costs, source load, and the effect of stale results matter.

TTL alone is not a universal bound on source-data age. That also depends on when and from where the value was loaded, plus failures and races. This exercise uses a current source, one key, and a controlled clock. Do not treat its timing model as a guarantee for every cache.

03 / TRY

Predict. Run. Inspect.

Enable JavaScript for the interactive experiment. The explanation and instructions remain readable below.

○ Lab observations not recorded yet

Make the experiment your own

  1. Keep TTL 10. Read at t=0 and predict the entry's expiry time.
  2. Change the source without advancing time. Read again and compare the returned value with the source.
  3. Advance five seconds twice. Inspect the entry lifetime before sending the next read. Did time alone load anything?
  4. Read after expiry and record the miss and new value.
  5. Try another TTL. Explain what changes and what does not. State an acceptable staleness rule for a hypothetical public dashboard.

These are application-cache observations, separate from browser HTTP caching. Disabling Chrome's browser cache does not clear this model or a real shared application cache.
