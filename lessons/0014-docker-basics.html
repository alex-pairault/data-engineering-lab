02 / EXPLORE

Follow the mechanism.

An image packages files and runtime configuration. A container runs an isolated process using an image and a writable layer. Several containers can use the same image. Ordinary runtime writes change that container's layer, not the original image. 

Browser → 127.0.0.1:18080 → published mapping → container port 8000
Image → new container writable layer → removed with that container
Named volume → mounted at /data → survives container removal

Stopping a container stops its process and retains the container and writable layer. Starting that same container can read its previous files. Removing it discards its writable layer; a replacement starts from the image again.

A named volume stores data outside that writable layer. Mounting it at /data puts the counter file there. It survives container removal until the volume itself is removed. Persistence is not a backup, and mounting can obscure files already at the destination.

-p 127.0.0.1:18080:8000 publishes a loopback host port mapped to the container's port. It does not change the application's internal listener. EXPOSE documents a port; it does not publish it. Inside the container, the teaching server binds 0.0.0.0:8000 so traffic arriving through the container interface can reach it.

The Dockerfile copies the app, selects a runtime, and sets the command. The base tag can move: for a fixed snapshot, record or pin its digest and the build inputs. The exercise also supplies CPU and memory limits, revisiting lesson 7; limits constrain resources but do not prove good performance.

The browser models the lifecycle only. Real practice requires a working Docker installation; setup and image download may take additional time. The supplied single-process counter is a local teaching service, not a production server or concurrency-safe database.

Make the experiment your own

  1. In the model, create without a published port and try POST. Remove the demo container.
  2. Create with a published port and writable-layer storage. Increment, stop, and start the same container. Observe retention.
  3. Remove and recreate with the same storage choice. Observe the counter reset.
  4. Repeat with the named volume: increment, remove, and recreate with that volume. Observe retention.
  5. For actual Docker practice, download docker_counter.py, Dockerfile, and the command guide into a new exercise folder. Follow the guide and record actual results. Use your own unique container and volume names if the example names already exist.
