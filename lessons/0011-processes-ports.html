02 / EXPLORE

Follow the mechanism.

A process is a running program instance. Its PID identifies that process on its host. A port is part of a network endpoint, alongside an address and protocol. A process can listen on several ports or none; a PID is not a port number. 

Client: 127.0.0.1:8000 → listening process → route /health → HTTP 200
Client: 127.0.0.1:9000 → no listener in this demo → connection refused
Client: 127.0.0.1:8000 → route /missing → HTTP 404

A listener accepts connections at a bound endpoint. 127.0.0.1 is IPv4 loopback: this machine, in the current network namespace. 0.0.0.0 is an IPv4 wildcard bind address, not a destination to put into your browser. In containers, “this machine” needs extra care; revisit that in lesson 14.

In this controlled example, refusal means no matching listener accepted the connection. An HTTP 404 means an HTTP responder was reached, but it did not serve that route. It does not prove which deployment answered: check a service label or request log. Real failures can also involve firewalls, proxies, IPv6, or timeouts.

Environment variables are string-valued process configuration. Our Python service captures its label at startup. Changing a parent environment dictionary, shell setting, or file later does not automatically reload that value in the child. Plain Python does not automatically read a .env file. Some frameworks implement reloads; inspect their behaviour instead of assuming one.

The browser model uses fixed ports and no real socket. The downloadable probe starts one real child on an OS-selected loopback port, requests two routes, and stops its own child. Its small HTTP server is for local teaching, not production hosting.

Make the experiment your own

  1. Send a request before starting the modeled service. Notice that there is no HTTP status.
  2. Start on 8000. Request /health, then /missing. Compare connection and route outcomes.
  3. Change next-start configuration to 9000 while it runs. Request 8000 again: the current listener stays there. Request 9000 before restarting.
  4. Restart the model and request /health on 9000. Trace exactly what moved.
  5. Download and run service_probe.py: python service_probe.py. Find the child PID, OS-selected port, HTTP statuses, and startup label. The script closes its own process.

If a local command fails, bring the exact non-sensitive error to your teaching agent. Do not stop unrelated services to free a port.
