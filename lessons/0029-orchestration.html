02 / EXPLORE

Follow the mechanism.

Triggerschedule or event
→
ExecutionDAG or worker
→
Effectsacknowledgement + retry boundary

A scheduled workflow creates a run at a planned time and can express task dependencies. A queue distributes work to workers. A webhook delivers an event over HTTP. They describe different parts of a system and can be combined.

For the daily pipeline, extract must produce input before transform, and load must wait for transform. A schedule does not itself establish task success or correct dependency order. Avoid heavy processing at workflow-definition time; orchestration should coordinate bounded work.

For event work, delivery and acknowledgement can fail independently of the business effect. If an acknowledgement is lost after the effect commits, a broker may redeliver the event. Without idempotency, the same event can apply twice.

In the local SQLite example, the event identity and its counter update commit together. A duplicate changes nothing, and an error before commit rolls both back. This is a controlled database boundary, not a universal exactly-once guarantee for external services. The later Airflow lesson adds real task attempts to the dependency picture.
