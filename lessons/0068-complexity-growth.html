n names the size of an input. Here it is the number of list items. Time complexity describes how the amount of work grows as n grows. It is not a duration in seconds. Begin by choosing one operation to count: here, reading one item.

O(1), pronounced “big oh of one”, describes work bounded independently of n under the stated model. Reading an ordinary Python list item at a known valid index is the example. O(n), “big oh of n”, is linear growth: reading every item once takes n item reads. Doubling n doubles that count.

5n + 3 is still linear: a fixed multiplier and a fixed extra cost do not change its growth family. Constant work need not be one machine instruction, and an O(1) operation can still take noticeable time. Our examples assume small fixed-size numbers and constant-cost primitive operations.

Big-O formally gives an eventual upper bound, not an exact count. In this course, “identify the complexity” means give the tightest usual growth family for the named case. We will name worst-case or expected assumptions where they matter. A few measured sizes illustrate the pattern; reasoning about the code explains why it continues. 

# One selected read (nonempty input): 1 read.
value = items[0]
# Every input item: n reads.
for value in items:
    total += value
