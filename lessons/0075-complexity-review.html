The starter finds duplicate IDs using a growing list of seen values. For all-distinct input, repeated list membership needs about n(n−1)/2 equality checks: O(n²). A set can reduce expected work to O(n) with O(n) auxiliary entries under ordinary fixed-size hashing. A duplicate found early has a different path.

Correctness tests alone accept both versions. The prepared counting keys also record hashing and equality events for ordinary distinct hashes, exposing the starter on n=16 and n=64. This checks those paths, not every possible key distribution. Pathological collisions can worsen set lookups; do not call the improvement a worst-case O(n) guarantee. 

seen = []
for item in ids:
    if item in seen:  # scans a growing list
        return True
    seen.append(item)
return False
