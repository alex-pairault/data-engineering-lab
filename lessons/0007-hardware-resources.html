02 / EXPLORE

Follow the mechanism.

A script uses a chain of resources. The CPU executes instructions; RAM holds active objects; storage and network I/O move data. CPU hardware caches keep small amounts of nearby data. They are different from the browser/application caches in earlier lessons.

Measure work and waiting

perf_counter measures elapsed duration. process_time measures CPU time used by the current process, excluding sleep. A gap suggests investigating waits or scheduling; it does not precisely measure disk I/O.

Measure the right memory

tracemalloc reports traced Python allocations. Process peak RSS includes a larger memory picture and the interpreter baseline. Neither number is all physical RAM used by the computer.

Eager loading keeps every parsed record in a list. Streaming consumes one record at a time, provided the code does not retain all results. A bounded batch is a middle choice. Streaming can reduce peak memory without making the CPU computation faster.

RAM pressure can cause paging/swapping or an out-of-memory failure. Extra workers can add working sets and contention; extra CPU cores do not automatically make a serial Python loop parallel. The workload and runtime determine which concurrency strategy helps.

This exercise separates untraced timing runs from traced allocation runs, in fresh processes. Files are generated before measurement. OS file caching still affects observations; this is not a cold-disk benchmark or a guarantee of production speed.
