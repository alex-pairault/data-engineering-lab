02 / EXPLORE

Follow the mechanism.

Start with the grain: this result needs one row per customer. The requirement is to sum paid orders and show zero when a customer has no qualifying order.

LEFT JOINPreserve left-side customers
→
WHEREFilter joined rows
→
GROUP / SUMAggregate survivors

When no right-side row matches, a left join supplies NULL right-side columns. A later condition such as WHERE o.status = 'paid' rejects those rows. A customer with only pending orders also loses every joined row. The join did not promise that later filters would preserve them.

Put the qualifying-order condition in ON to preserve every customer. SUM ignores NULL inputs and returns NULL when there are no non-NULL inputs. COALESCE(SUM(o.amount), 0) supplies zero for a group that still exists. It cannot recreate a group already filtered away.

A second solution joins all orders and sums CASE WHEN status = 'paid' THEN amount ELSE 0 END. Compare both approaches on the same fixture before choosing.

Edge cases matter: multiple paid orders, only excluded orders, no orders, and a genuine paid zero. Adding OR o.id IS NULL to the broken WHERE clause still loses customers who matched only excluded orders.
