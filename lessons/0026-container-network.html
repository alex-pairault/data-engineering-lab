02 / EXPLORE

Follow the mechanism.

Hostpublished 18080
→
Proxy containerservice-name lookup
→
App containerinternal 8000 + volume

In an ordinary bridge-network container, loopback refers to that container. It does not mean the host or another service. Peer containers use a shared network and service DNS names with their internal listening ports.

The prepared stack publishes the proxy on host loopback port 18080. The proxy reaches app:8000 inside the project network. Using the host port as the peer’s internal port is a different mistake from using localhost. Container addresses can change on recreation; service names provide a more stable reference.

Startup order is not readiness. Compose can wait for a declared healthcheck with service_healthy, but applications must still handle later disconnections. A healthcheck’s scope matters: a listening HTTP process may not establish that every dependency or business operation is healthy.

The app’s synthetic counter lives in a named volume mounted at /data. Recreating the container retains it when the same volume is reused. Normal compose down retains named volumes; down -v removes declared named volumes. Keep this exercise in its own project, inspect the state, and do not clean up unrelated resources.
