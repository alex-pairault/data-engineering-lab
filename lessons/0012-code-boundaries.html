02 / EXPLORE

Follow the mechanism.

A boundary gives a responsibility a clear home. Here the product rule is simple: valid amounts are integer cents from 0 to 1000000; the discount is 10%, rounded down to whole cents. The saved total is amount minus discount.

HTTP / jobTranslate caller input
→
Application + domainCoordinate; enforce valid total
→
StoragePersist valid result

The HTTP adapter translates a request body into values and maps results or errors to HTTP responses. A job has a different adapter. Neither should need a copy of the discount formula.

The domain function expresses the business calculation and invariant: valid amount, one rounding policy, one result. A pure function returns a value without HTTP, database, or file effects. The application operation coordinates the domain call and a subsequent save. The storage adapter handles how the valid result is persisted.

The browser's duplicated version has drifted: HTTP uses 10%, the job 5%. For 10000 cents, they save 9000 and 9500. Sharing the domain function makes both follow the same rule. Check an odd amount too, so rounding is deliberate.

HTTP field validation improves feedback but cannot replace domain validation. A job can bypass the HTTP handler. Both callers must reject negative, non-integer, or oversized amounts before storage. Database constraints can protect persisted state as well; Python validation does not make them unnecessary.

These are logical responsibilities, not a requirement for separate servers, classes, or a repository framework. The downloadable exercise uses small functions and an in-memory repository. It demonstrates structure and behaviour, not production persistence or authentication.
