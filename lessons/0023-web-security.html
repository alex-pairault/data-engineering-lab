02 / EXPLORE

Follow the mechanism.

Inputuntrusted note text
→
Query boundaryconcatenate or bind
→
Rowsowner must remain scoped

SQL injection changes how a query is interpreted when untrusted text becomes syntax. In this local search, concatenation can turn an intended owner-scoped predicate into an OR expression that returns another owner’s rows.

Parameter binding keeps input values separate from SQL structure. Bind the authenticated owner and search text. The same injection-shaped value then matches no note; an ordinary apostrophe is handled as data. Binding values does not automatically provide authorization, and identifiers such as table names need fixed mappings or allowlists rather than value placeholders.

Keep related web risks distinct. XSS runs attacker-controlled browser code; context-appropriate output handling is needed. For ordinary element text, textContent avoids HTML parsing. CSRF induces an authenticated browser action; it needs an appropriate server defense, not merely cookie authentication or CORS. HTTPS protects transport but does not remove these application risks.

The focused exercise executes read-only SQLite searches on synthetic rows. It does not attack a real site or provide a full production security implementation. The tangible win is showing that unsafe query construction widens results while the bound owner-and-value query preserves the intended boundary.
