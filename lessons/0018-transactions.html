02 / EXPLORE

Follow the mechanism.

→
Write boundarystale value or guarded update
→
Resultaccepted count + remaining stock

A race occurs when overlapping operations depend on an ordering that the application has not protected. Two callers can both decide to sell the final unit using a stale value. A nonnegative-stock CHECK can still pass while two sales were accepted: both blind writes store zero.

Control the interleaving instead of hoping sleeps reproduce it. In this exercise both reads happen before either protecting write transaction. Each later write commits independently. This is not a claim that SQLite permits two simultaneous protected writers; SQLite serializes writers and can reject conflicting transactional patterns.

For this single-row rule, perform UPDATE stock SET quantity = quantity - 1 WHERE quantity > 0 and inspect the affected-row count. Only the operation that changes one row may record a sale. Keep the update and its sale record in the same transaction. A different multi-row invariant may need additional constraints, locking or isolation reasoning.

A transaction commits its database unit together or rolls it back on failure. It does not automatically eliminate every application race or undo an external email/payment. Database isolation behaviour differs; name the engine and transaction boundaries when explaining a concurrency example.
